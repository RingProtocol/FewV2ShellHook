FewV2ShellHook is a Uniswap v4 hook that exposes an origin-token shellPool while routing all actual swap execution through the corresponding canonical Ring Swap v2 FewToken pair. For example, an A/B shellPool can route swaps through the existing fwA/fwB pair on Ring Swap v2. The shellPool is an interface and settlement layer. It is not the swap execution venue and adds no Ring fee. The FewV2 pair charges its standard 30 bps LP fee. This undeployed candidate also accounts for configured Uniswap protocol fees using the Aggregator family flag and 25× fee multiplier; the current Uniswap fee controller supplies the TokenJar recipient.

During beforeSwap, the Hook takes the origin-token input from PoolManager, wraps it into the canonical FewToken, sends the wrapped input directly to the FewV2 pair, executes the swap, unwraps the FewToken output, and settles the origin-token output with PoolManager. It then returns the complete BeforeSwapDelta to the shellPool. Both exact-input and exact-output swaps must fill completely. If the direct pair is unavailable, its reserves are empty, PoolManager input inventory is insufficient, wrapper backing is insufficient, the requested price limit is crossed, or the swap cannot be fully executed, the transaction reverts. The Hook never falls back to the shellPool curve or to a caller-supplied pair.

The route is registered when the poolInitializer initializes a shellPool. The Hook derives both wrappers from FewFactory and the direct pair from the configured FewV2Factory, then verifies that the wrappers are canonical, their underlying tokens match the shellPool currencies, and the pair contains those exact FewTokens. Callers cannot select or override the route through function arguments or hookData. A FewV2 pair can be registered only once per Hook deployment, and a registered route cannot be changed. Native ETH and WETH modes require separate Hook deployments. Only one shell route should remain active for each FewV2 pair across deployments.

FewV2ShellHook also includes a minimal governance layer on top of this swap path: an underlying-token allowlist checked when a shellPool is initialized (new entries take effect only after an immutable 48-hour timelock), an emergency swap pause, a two-step owner that cannot be renounced and a disable-only guardian. The guardian can pause swaps and remove allowlist entries but can never add a token or unpause. The owner can replace the poolInitializer and the residual recipient; a new poolInitializer can only register new shellPools. No role can upgrade the contract, change a registered route, move PoolManager assets or withdraw another account's liquidity, and pausing swaps never blocks liquidity withdrawal.

Uniswap or an aggregator can discover the shellPool's available depth through the IAggregatorHook interface. For an initialized shellPool PoolKey, compute its PoolId using the standard Uniswap v4 PoolKey hashing method, then call pseudoTotalValueLocked(PoolId) on the Hook. The function returns the live FewV2 reserves in shellPool currency order, capped by the corresponding wrapper backing and PoolManager origin-token inventory. The ABI is:

function pseudoTotalValueLocked(bytes32 poolId) external view returns (uint256 amount0, uint256 amount1)

The Hook also exposes quote(bool zeroToOne, int256 amountSpecified, bytes32 poolId) through IAggregatorHook. Negative amountSpecified represents exact input and positive amountSpecified represents exact output. The quote simulates the complete shellPool swap through the official V4Quoter, including PoolManager input inventory, wrapper backing, wrapping, the FewV2 swap, unwrapping, settlement, price-limit checks, and full-fill checks. It models swap-before-payment, so a settle-first exact-input transaction may be executable even when this conservative quote rejects insufficient starting PoolManager inventory. The function is intended to be called through eth_call because V4Quoter uses revert-based simulation and is intentionally not declared view. The simulation does not persist state or consume transaction gas when called through eth_call.

Protocol fees are collected in origin tokens: exact-input deducts a rounded-up fee from gross output, while exact-output adds a rounded-up fee to venue input. The complete V4Quoter simulation includes the fee once. A configured fee with a missing or zero TokenJar recipient makes quote and execution revert; it is not silently waived. The Hook owner cannot set the fee rate, multiplier or fee recipient. This candidate needs a new verified deployment and a new routing review; the existing 0x5925 deployment remains unchanged.

A separate SubsidyVault can refund that Uniswap protocol fee to the trader from a shared Ring budget, which brings the Shell quote back on par with a plain v4 pool at the same fee tier. The refund is capped at the protocol fee that was just charged, is paid out of Ring's budget rather than the Shell LP, and leaves the Hook's own balance untouched. It fails open: an unarmed, paused or empty vault means no subsidy and the route keeps working. It does not change how the protocol fee is charged or who receives it.
